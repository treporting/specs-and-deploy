# Demonstration of SR_09 2.2.1 with pull request #502

## Requirement

SR_09: on every pull request, in .github/workflows/tools.yml, check every review result the pull
request adds or changes against its base commit, and fail where a result breaks a rule; a pull
request whose check failed cannot be merged

## Configuration

- `.github/workflows/tools.yml` and the tools as on `main` at `d49c98c`: the job `reviewcheck` runs
  `reviewcheck -root .. -base "$BASE"`, the base commit of the pull request
- the ruleset of `main` as in `.github/rulesets/main.json` at `bd17c6b`, with reviewcheck a
  required check and no bypass

## Steps

1. From `main` at `d49c98c`, add a review result whose criterion RC_01 is missing:
   `reviews/results/20261105T090000_demonstration.yaml`, a copy of the review result of
   tools/README.md 33.1.1 without its line `RC_01: passed`. Open pull request #502 with it, commit
   `dc2636b`.
2. Wait until the job reviewcheck of run 41991188519 has run.
3. Read the log of the job reviewcheck, and the state of the merge: `gh pr view 502 --json
   mergeStateStatus`.
4. Close the pull request unmerged. GitHub keeps it and its commit.

## Expected

The job reviewcheck checks only the review result the pull request adds - not the 234 on `main` -
fails on the rule it breaks, and the merge of the pull request is blocked.

## Observed

From the log of reviewcheck:

```
reviews/results/20261105T090000_demonstration.yaml RR_01: criterion RC_01 is missing
1 review results checked, 1 findings
Process completed with exit code 1.
```

The state of pull request #502: `OPEN BLOCKED`. Every other required check passed.
