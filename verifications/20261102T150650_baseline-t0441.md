# Demonstration of SR_82 with the baseline T0441

## Requirement

SR_82: in baseline.yml, after licencecheck, check the approvals of every approved object of the
head of main, and fail where one is reported

## Configuration

- `.github/workflows/baseline.yml`, `.github/build/steps.sh` and `tools/review` as on `main` at
  `eef8e1e`
- the GitHub App `treporting-baseline` with the organization variable `BASELINE_APP_CLIENT_ID` and
  the secret `BASELINE_APP_PRIVATE_KEY`, as devops.md, section Baseline, describes it

## Steps

1. Issues, New issue, Baseline: title Baseline T0441, field Label `T0441`; ticket #418.
2. Set the label `baseline` on #418.
3. Read the log of the job sbom and the pull request the run opened.

## Expected

The job sbom runs approvalcheck after licencecheck on every approved object of the head of main;
it reports no finding, and the run opens the pull request.

## Observed

The run at `eef8e1e`, every job passed: start, build, lint, report, test, sbom and result.

From the log of the job sbom:

```
== .: /tmp/tmp.6Px8asIdrp/sbom -label T0441 -ticket 418
sbom.md written: 13 packages, version 2.1.1
== .: /tmp/tmp.bTNfUoDANN/licencecheck -root .
13 packages checked, 0 fail
== .: /tmp/tmp.vZol2qP9o8/approvalcheck -root .
approvals checked, 0 findings
```

The App opened the pull request #419 and named it in #418. Its checks passed, `approvalcheck`
among them. It was merged as `3f7761b`, and the signed tag T0441 set on it.

The case with a finding is not shown: on the head of main it would need an approval that is not
correct, and every pull request runs the same check on its changed files (SR_81).

## Verdict

Passed: the job sbom ran approvalcheck after licencecheck on the head of main, on every approved
object, without a finding, and the run went on to the pull request.
